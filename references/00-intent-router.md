# 00 · 意图识别与风格路由

> P0 / P1 的操作手册。目标：从一句人话里读出「做什么、给谁、什么调性、参考谁」，并落到 1 个主品牌规范 + 至多 1 个辅参考。
> 品牌清单与分族见 `01-brand-taxonomy.md` / `data/brand-index.json`。

---

## 1. 设计读法（Design Read）

先读这 6 个信号，再说话：

| 信号 | 要读出的东西 | 例 |
|---|---|---|
| 产物类型 | 落地页 / 官网 / 产品后台 / 工具类应用 / 内容站 / 作品集 / 小程序 / App | 「给我做个官网」≠「做个后台」 |
| 受众 | 技术买家 / 消费者 / 招聘方 / 内部运营 / 监管行业 | 受众定调性，不是模型品味 |
| 氛围词 | 用户原话 | 「高级」「干净」「有科技感」「温柔」「狠一点」 |
| 参考物 | 链接 / 截图 / 竞品 / 品牌名 | 有参考物时优先于形容词 |
| 既有资产 | logo、品牌色、已有 UI、字体 | 有品牌资产时不许另起炉灶 |
| 硬约束 | 合规、无障碍、政企、儿童、性能、端 | 约束优先于审美 |

### 输出格式（必须给，让用户有机会否决）

```text
Design Read：这是 <产物类型>，给 <受众>，语言是 <氛围词>，倾向 <品牌/风格族>。
表盘：VARIANCE=<n> MOTION=<n> DENSITY=<n>（理由：一句话）
主参考：<brand>（keep：… / change：… / do-not-copy：…）
辅参考：<brand 或 none>（只借 <一个维度>）
置信度：0.x
```

### 表盘（三个旋钮）

| 旋钮 | 1 | 10 | 影响 |
|---|---|---|---|
| `VARIANCE` 布局张力 | 绝对对称 | 实验性错位 | 是否居中 hero、是否用非对称栅格、bento 是否规则 |
| `MOTION` 动效强度 | 静态 | 电影感 | 时长、位移、是否滚动驱动 |
| `DENSITY` 信息密度 | 画廊级留白 | 驾驶舱级密集 | 间距、字号档位、每屏信息量 |

推断规则（信号 → 值）：

| 信号 | VARIANCE | MOTION | DENSITY |
|---|---|---|---|
| 极简 / 干净 / 克制 / Linear 类 | 4–6 | 2–4 | 3–5 |
| 高端消费 / Apple 类 / 奢侈品 | 6–8 | 4–6 | 2–4 |
| 活泼 / 创意 / Awwwards / 工作室 | 8–10 | 7–10 | 3–4 |
| 政企 / 医疗 / 金融合规 / 无障碍优先 | 2–4 | 1–3 | 4–6 |
| 数据后台 / 运营台 / 表格密集 | 3–5 | 2–3 | 7–9 |
| 改版（保留品牌） | 沿用现状 | 现状 +1 | 沿用现状 |
| 改版（重做视觉） | 现状 +2 | 现状 +2 | 沿用现状 |

**表盘只影响「怎么排」，不豁免正面/反面清单。**

## 2. 置信度与提问协议

| 置信度 | 依据 | 动作 |
|---|---|---|
| ≥ 0.8 | 有明确参考物或多次同风格上下文 | 直接给读法，开始 P1 |
| 0.6–0.8 | 氛围词清楚、产物清楚 | 给读法 + 1 句「如果更想要 X 方向可以说」，继续 |
| 0.5–0.6 | 只有一个模糊形容词 | 给 **2–3 个品牌对比选项**，各自说明代价，让用户选 |
| < 0.5 | 连产物类型都不确定 | 只问 **1 个** 问题：先定产物类型与受众 |

### 提问硬规则

1. 一次最多 **2 个** 问题，优先 1 个。
2. 选项必须是可视觉化的对比（品牌/风格族/具体做法），不是形容词菜单。
3. 每个选项必须写「代价」：选它会牺牲什么。
4. 能从上下文推断的不问；不确定的写「我按 X 推断，若不对告诉我」。
5. 禁止：「你想要什么风格？」「请描述你的需求」「你喜欢什么颜色？」。

### 好例子

> 我读成：给开发者的 API 文档站，偏冷、克制，倾向 Vercel 的极简。
> 如果你想更「有产品感」一点，也可以走 Linear 的深色精密路线——代价是纯内容站会显得偏重。要哪个？

> 两个方向：A. Stripe 式（浅色、克制、金融可信，适合转化）B. Linear 式（深色、工程感，适合技术受众）。差异主要在首屏：A 是「可信」，B 是「专业」。你更想让人第一眼觉得哪个？

## 3. 十个风格族（路由目标）

> 判别顺序：先看产物类型与受众，再看氛围词，最后看参考物。命中多个时取「产物类型匹配度」最高的。

### F1 devtools-dark · 深色工程感开发者工具
- **关键词**：开发者、API、SaaS、终端、工程感、精密、深色、mono、dashboard
- **代表**：Linear、Vercel、Raycast、Supabase、Warp、x.ai（完整 17 个见 01 §1）
- **特征**：近黑画布 + 半透明描边 + 单一强调色 + 负字距大标题 + mono 辅助
- **表盘**：V4–6 / M2–4 / D5–7
- **适用**：开发者工具、B2B SaaS、技术产品落地页
- **失败模式**：深色 + 紫色渐变 + 发光按钮 = 典型 AI 味；深色底上低对比灰字

### F2 premium-minimal · 高端极简 / 消费电子
- **关键词**：高端、极简、消费电子、Apple 感、留白、产品摄影、精致
- **代表**：Apple、Superhuman、Cal.com
- **特征**：大留白、超大产品图、极少文字、单一强调、克制动效
- **表盘**：V5–8 / M3–6 / D2–4
- **适用**：硬件/消费品官网、品牌站、发布会页
- **失败模式**：把「高端」做成米色+黄铜+衬线（AI 默认豪华配方）；图片质量撑不起留白

### F3 fintech-trust · 金融科技信任感
- **关键词**：金融、支付、银行、信任、安全、合规、数据、B 端
- **代表**：Stripe、Coinbase、Wise、Revolut、Kraken
- **特征**：浅色为主、克制的蓝/绿强调、精细图表、强对比排版、明确的数字层级
- **表盘**：V3–5 / M2–4 / D5–7
- **适用**：支付、金融、保险、财税、B 端数据产品
- **失败模式**：蓝紫渐变 + 玻璃卡片；用「未来感」替代「可信感」

### F4 enterprise-system · 企业级系统 / 文档密集
- **关键词**：企业、后台、管理台、文档、表格、设计系统、可访问性、多语言
- **代表**：IBM、Notion、Airtable、Mintlify（HashiCorp/ClickHouse/Sentry/PostHog/Expo 归 F1）
- **特征**：结构化栅格、密集但清晰、语义色系统、组件优先、深浅双主题
- **表盘**：V2–4 / M1–3 / D6–8
- **适用**：内部系统、文档站、数据平台、控制台
- **失败模式**：把后台做成营销页；表格/表单缺状态；对比度不足

### F5 ai-native · AI 原生产品
- **关键词**：AI、模型、Agent、生成、推理、多模态、前沿
- **代表**：Claude、Cohere、Mistral、Runway、ElevenLabs、Replicate
- **特征**：常深色但更「安静」；mono 点缀；大量留白与短句；几乎不用渐变
- **表盘**：V4–7 / M3–6 / D3–5
- **适用**：AI 产品、模型公司、Agent 工具
- **失败模式**：紫蓝渐变 + 光斑 + sparkles 图标 + 「未来已来」文案——最重的 AI 味重灾区

### F6 creative-tool · 创意工具 / 画布
- **关键词**：设计工具、协作、画布、创意、作品集、视觉编辑
- **代表**：Figma、Framer、Webflow、Miro、Clay
- **特征**：色彩更敢用、图形语言强、界面本身就是展示品
- **表盘**：V6–9 / M5–8 / D3–5
- **适用**：创意工具、设计平台、作品集
- **失败模式**：为了「创意」堆动效；颜色多但没有系统

### F7 editorial-brand · 编辑感 / 品牌叙事
- **关键词**：品牌、杂志、编辑、叙事、大字、排版驱动、文化
- **代表**：Resend、Cursor
- **特征**：大字排版、非对称栅格、系列化内容、克制色彩 + 强字体
- **表盘**：V6–9 / M3–6 / D2–4
- **适用**：品牌站、内容专题、发布页
- **失败模式**：衬线滥用（Fraunces/Instrument Serif）；大字但没有网格

### F8 consumer-warm · 消费 / 生活 / 好友好
- **关键词**：消费、生活方式、旅行、社交、轻松、温暖、可爱
- **代表**：Airbnb、Spotify、Uber、Pinterest
- **特征**：圆润、图像驱动、色彩温暖、卡片化但不滥用
- **表盘**：V5–8 / M4–7 / D3–5
- **适用**：C 端产品、社区、内容消费
- **失败模式**：圆角+阴影+渐变三件套；图标风格混用

### F9 industrial-bold · 工业 / 汽车 / 硬朗力量
- **关键词**：汽车、工业、机械、硬朗、性能、力量、运动
- **代表**：Tesla、Ferrari、BMW、NVIDIA、SpaceX、Lamborghini、Renault
- **特征**：大字、强对比、动感构图、金属/暗色质感、少量高饱和点睛
- **表盘**：V7–10 / M6–9 / D3–5
- **适用**：汽车、硬件、运动、工业品牌
- **失败模式**：堆特效；红色滥用（法拉利红无节制）

### F10 commerce-conversion · 电商 / 营销转化
- **关键词**：电商、转化、定价、活动、促销、增长、落地页
- **代表**：Zapier、Intercom（Stripe 定价页只作辅参考结构）
- **特征**：清晰层级、强 CTA、社会证明、价格表、A/B 友好结构
- **表盘**：V4–7 / M3–6 / D4–6
- **适用**：落地页、定价页、活动页、商品页
- **失败模式**：三张等宽功能卡 + 居中 hero + 假数据社会证明

> 每个品牌归族、关键词、适配/避坑，见 `data/brand-index.json` 与 `01-brand-taxonomy.md`。

### 3.1 路由注意（来自 58 品牌分族的实测经验）

1. **「深色」不是 F1 独占**：F5（Framer/Sanity）、F9（Lamborghini/SpaceX）、F7（Resend）都可能很深。判族先看**行业/受众**，再用品牌 `theme` 数组做硬过滤。
2. **F10 多为辅族**：9 个品牌的 secondary 是 F10。用户说「SaaS 落地页」时主族常是 F1/F4，F10 只提供转化结构（定价表、社会证明、CTA 节奏）。
3. **F2 / F7 / F10 是稀有族**（各 2–3 个品牌）：选型时优先保证「族对」，不要为了多选项而错族。
4. **没有匹配族时不要硬套**：儿童 / 教育 / 医疗严肃 / 政务等语境，58 个品牌全是商业与开发者语汇，直接套会「像另一个行业」。此时：
   - 明确告诉用户「索引里没有同行业参考，我建议用 F4 的信息结构 + F2 的克制」；
   - 把「不套品牌、自定义语言」写进 guidelines 的 keep/change，并提高反面清单权重（更容易滑向 AI 默认）。
5. **同族品牌差异很大**：F1 里 Linear（精密深色）与 PostHog（土色手绘）几乎是两个世界。定族后必须再读 1–2 个候选品牌的 `one_liner_zh` + `signature` 才能定主参考。

## 4. 品牌选择算法

1. **定族**：按 §3 得到 primary family（可加一个 secondary family）。
2. **筛品牌**：在该族内按 `best_for` 命中产物类型、`avoid_for` 排除；再按 `ai_slop_risk` 优先 low。
3. **定角色**：
   - **主参考（1 个）**：定整体语言——配色体系、字体气质、密度、形状系统。
   - **辅参考（0 或 1 个）**：只借 **一个维度**（例如「只借 Stripe 的定价表结构」），不许混两套语言。
4. **写 keep / change / do-not-copy**（强制三段，缺一段不允许进 P2）：

| 段 | 含义 | 例（参考 Linear） |
|---|---|---|
| keep | 保留的可控品质 | 近黑画布、半透明描边、单一强调色、负字距标题 |
| change | 要改成我们自己的 | 品牌名/logo、文案、信息架构、具体栏目、产品截图 |
| do-not-copy | 绝不照搬 | Linear 的实际 logo、版权图、精确布局、原文案、专有组件 |

5. **同族轮换**：同一用户/项目连续做多个页面时，不要连续用同一主参考；至少在族内换一次，避免「所有项目一个味」。

## 6. 反模式（路由阶段）

- ❌ 直接开始写代码，不给 Design Read。
- ❌ 用户说「高级」就默认米色+黄铜+衬线；说「科技感」就默认紫蓝渐变；说「AI 产品」就默认光斑+sparkles。
- ❌ 一次给 5 个品牌让用户挑（选择过载）——最多 3 个，且必须说明差异与代价。
- ❌ 主参考是 A、辅参考是 B，最后两套语言混着用。
- ❌ 参考品牌含紫色/玻璃/大圆角，就无脑照抄——先看 `03-negative-list.md` 的例外条件。
