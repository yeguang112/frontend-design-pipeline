# 07 · 变更控制与防漂移

> 长期项目里，AI 不是「不会做」，而是「做着做着忘了」。这一章把「不忘」变成流程：
> **每次会话先读 → 每次改动先判影响面 → 每次改完跑矩阵 → 每次偏差都记录。**

---

## 1. 三道闸

```text
闸 1（进入）：读权威源 → 回述约束 → 再动手
闸 2（改动前）：判影响面 → 决定是否 CR → 决定验证范围
闸 3（改动后）：八项自检矩阵 → 记录 → 截图
```

三闸缺一不可。跳过闸 1 是最常见的漂移起点。

---

## 2. 闸 1：会话开始仪式（3 分钟）

任何涉及 UI 的会话/任务，先按顺序读：

1. `design/design-authority.md` —— 权威源与冲突裁决
2. `design/frontend-guidelines.md` —— 正/反清单（重点是反面清单）
3. `design/components.md` —— 可用组件清单
4. `design/decision-log.md` 最近 3 条 —— 用户最近否掉了什么
5. `design/tokens/tokens.css` —— 可用值

> **首次项目还没有这些文件时**（P0–P2 阶段）：改为读 `SKILL.md` + `references/00-intent-router.md` + `02-guidelines-spec.md`，并在 P4 冻结后补建上述文件；不要因为文件不存在就跳过闸 1。

然后**用 5 行回述**给用户：

```text
当前设计权威：<项目> v1.x（冻结于 <日期>）
主参考：<brand>；表盘 V/M/D
我会遵守：<3 条最容易被违反的反面清单>
可用组件：<数量>；不允许新建
本次任务影响面：<token/组件/布局/文案>
```

**没回述就动手 = 违规。**

---

## 3. 闸 2：影响面判定

| 改动类型 | 例子 | 影响面 | 是否 CR | 验证范围 |
|---|---|---|---|---|
| 文案 | 改标题、按钮文字 | 无 | ❌ | 截图 1 张 |
| 修 bug | 对齐、溢出、错别字 | 局部 | ❌ | 该屏截图 + drift |
| 样式微调 | 间距/颜色**用现有 token** | 局部 | ❌ | 该屏截图 + token 断言 |
| 值变更 | 改 token 值、新增颜色/字号 | tokens | ✅ | 全量截图 + diff |
| 组件变更 | 改尺寸/状态/新增变体 | components | ✅ | 组件 3 态截图 |
| 新组件 | 契约里没有 | components | ✅ | 契约 + 3 态 |
| 布局调整 | 栅格、区块顺序、新增屏 | 视觉真相 | ✅ | 全量截图 |
| 换风格 | 换主参考/表盘 | 全部 | ✅ + 重走 P1/P2 | 重冻结 |

判定口诀：**「用户能不能在截图里看出来？」看出来 = 至少 P3 级验证；「值变没变？」值变 = CR。**

---

## 4. 闸 3：八项自检矩阵（每次 UI 改动必跑）

| # | 维度 | 检查什么 | 怎么查 | 通过标准 |
|---|---|---|---|---|
| 1 | **布局** | 栅格对齐、间距、溢出、断点 | 三档截图 + `scrollWidth` 检测 | 无溢出；间距 ∈ spacing scale；对齐 8pt |
| 2 | **Token** | 是否只引用 token | `detect-drift.mjs` | error = 0；无裸值 |
| 3 | **字体** | 家族/字号/字重/行高/字距 | 计算样式断言 | 全部 ∈ typography token；≤2 家族 |
| 4 | **交互** | 状态齐全、键盘、焦点 | 状态截图 + 键盘走查 | 状态矩阵无缺项；`:focus-visible` 可见 |
| 5 | **图标** | 同一套、同 stroke、尺寸 | 目测 + grep | 无 emoji；无手搓 SVG；stroke 一致 |
| 6 | **内容** | 真实文案、无假数据、CTA 不重复、**无提示词泄漏** | `check-copy.mjs` + 目测 | error=0；无 lorem/假指标；一个意图一个 CTA；说明类文字只在注释里 |
| 7 | **无障碍** | 对比度、alt、语义、aria | 对比度脚本 + 人工 | 正文 ≥4.5:1；图片有 alt；可键盘操作 |
| 8 | **性能** | 图片尺寸、字体加载、无布局抖动 | 截图 + 简易指标 | 图片有宽高；无外链字体；CLS 可接受 |

**矩阵结果写进 change-log，一行一条改动。**

## 5. 防漂移机制（比自觉更可靠）

### 5.1 设计指纹（Design Fingerprint）

在 `design-authority.md` 里存一份「指纹快照」，任何一次改版后对比：

```json
{
  "accent": "#2563eb", "bg": "#ffffff", "fg": "#111113",
  "fontDisplay": "Geist", "radiusCard": "14px", "buttonHeight": "40px",
  "density": 6, "variance": 5, "motion": 3,
  "signature": ["单强调色", "实底卡片", "负字距标题"]
}
```

指纹变了 = 方向变了，必须走 CR 并说明原因。

### 5.2 守卫清单（Guardrails）

写进 `design/design-authority.md` 的「不可协商项」。冲突裁决统一见 `02-guidelines-spec.md` §7；需要例外时**只能走 CR**，并写进 guidelines 的例外字段，不得口头放行。

```md
## 不可协商（任何改动都不得违反）
- 一个强调色，只出现在主 CTA 与选中态
- 不使用渐变（品牌规范明确指定的除外）
- 不用玻璃/模糊材质
- 圆角只有 6/10/14/999 四档
- 组件只来自 components.md
- 动效只有 200ms 进入 / 140ms 退出
```

### 5.3 漂移症状自查（出现即停手）

| 症状 | 可能原因 | 处理 |
|---|---|---|
| 新页面出现 spec 里没有的颜色/字号 | 没查 tokens | 回滚裸值，改用 token |
| 组件长得像但参数不同 | 自造变体 | 合并进契约或改用现有变体 |
| 页面越来越「卡片化」 | 用卡片代替布局 | 回到布局家族 |
| 动效越加越多 | 审美漂移 | 对照 MOTION 表盘 |
| 每版都「更好看」但风格不同 | 没有主参考/表盘失效 | 重走 P1，确认参考 |
| 用户反复说「不是这个感觉」 | guidelines 没沉淀 | 追加决策日志，改规则 |

### 5.4 周期性健康检查（每 5–10 次改动或每周）

```text
1. verify-freeze 校验冻结未被改
2. detect-drift 全项目 0 error
3. 截图矩阵抽 3 屏对比冻结参考
4. 读 decision-log，检查有没有「口头改了但没写进规则」的项
5. 更新指纹快照
```

## 6. change-log 格式

`design/change-log.md`，一次改动一条：

```md
### 2026-11-07 14:32 · 设置页
- 改动：新增「通知开关」行，复用 Switch 组件
- 影响面：无 token 变更；无新组件
- 矩阵：布局✅ token✅ 字体✅ 交互✅ 图标✅ 内容✅ a11y✅ 性能✅
- 验证：截图 acceptance/screenshots/settings--default--1440x900--light.png
- 备注：无
```

---

## 7. 反模式

- ❌ 每次新会话都「重新理解一下审美」，不读权威源。
- ❌ 用「这次特殊」当借口绕过规则（应走 CR）。
- ❌ 改完不跑矩阵，等验收时才发现。
- ❌ 规则文档与代码两套值（应只认 tokens）。
- ❌ 漂移发生时改规则迁就实现（应改实现或明确批准例外）。
